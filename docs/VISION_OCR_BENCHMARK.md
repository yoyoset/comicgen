# 视觉 OCR 模型评测（2026-11-06）

目的：选出「读中文竖排漫画气泡」最可靠的视觉模型，作为逐页审计与重新排字的读图端。

## 一、结论先行

| 模型 | 受控基准（10 格，标准答案由人核） | 实测表现 |
|---|---|---|
| **Muse Spark 1.3**（`opencode-go/muse-spark-1.3-contributor`） | **0 错，字符准确率 100%** | 稳定，偶尔把全角标点写成半角；长页不合并气泡 |
| **DeepSeek V4.1 Flash**（`opencode-go/deepseek-v4.1-flash`） | **1 错（漏字），99.4%** | 会诚实标 `?`；偶发漏掉重复字（「哈哈哈」→「哈哈」） |
| **MiMo-V2.6-Flash**（`opencode-go/mimo-v2.6-flash`） | 见下表 | 多次出现 `Upstream request failed [400]`，整批不返回 |

**选型建议（2026-11-06 定案，后续沿用）**：
- **生产转录统一用 Muse Spark 1.3**（`opencode-go/muse-spark-1.3-contributor`），受控基准 10/10 全对。
- 需要交叉复核时才用 DeepSeek V4.1 Flash（`opencode-go/deepseek-v4.1-flash`），它会偶发漏重复字。
- **MiMo-V2.6-Flash 放弃**：两次整批 `Upstream request failed [400]`，出不了结果，不进生产。

## 二、受控基准（怎么测的，可复现）

不看模型自述，也不让它读整页——**读的是编号联系表**（`scripts/make_region_sheet.py`），
每格独立裁切放大，模型只回答 `{#序号: 文字}`。

- 测试页：`七龍珠 全彩版 第17卷` 的 `0125`（8 格，短句+拟声）、`0147`（2 格，长句）。
- **标准答案由编排模型逐格人工核联系表得出**，不是任何模型自己的输出：

`0125.jpg`

| 格 | 标准答案 |
|---|---|
| 0 | 给我滚出来——！ |
| 1 | 我懂了！卡卡洛特也来了……！ |
| 2 | 看来你是想找死…… |
| 3 | 啊…啊…？ |
| 4 | 悟饭的气增强了——！ |
| 5 | 呼… |
| 6 | 太棒了！ |
| 7 | 嗯？ |

`0147.jpg`

| 格 | 标准答案 |
|---|---|
| 0 | 哈哈哈！弗力札大王一定会很高兴的！我记得龙珠只要凑齐七颗就可以了吧？ |
| 1 | 后面有五颗，你们手上有两颗…呵呵呵……已经齐了啊！ |

（两页的页脚「弗力札篇—2 ★xx」属于版式文字，不计分。）

评分用**编辑距离**（`difflib.SequenceMatcher`），不用逐位比对——
一个字漏掉会让后面所有位置错位，逐位比对会把 1 个字算成 30% 错误。

## 三、逐模型明细

### Muse Spark 1.3

10 个格全部正确。唯一系统性差异：标点写成半角（`!` `?` `,`），
以及把「呵呵呵……」压成「呵呵呵…」——**属标点层面，不影响语义**，
后处理统一转全角即可。

### DeepSeek V4.1 Flash

1 处实质错误：0147#0 把「哈哈哈！」读成「哈哈！」（漏一个重复字）。
其余 9 格正确，标点规范（全角），不确定处愿意标 `?`。

### MiMo-V2.6-Flash

本轮受控基准未取到结果：两次整批返回 `Upstream request failed [400]`。
历史批次（七龙珠 17 卷 0016–0030 / 0064–0078 等段）也曾卡死不出结果，
最终都由 DeepSeek/Deepseek 重发补上。**结论：不作为主力**。

## 四、为什么仍然要「编号裁切 + 逐格」

整页读一次，任何模型都会出现**气泡合并**（Muse 在死神 18 卷 0137 把两句并成一句）
和**漏字**（DeepSeek 漏「没」）；这类错误直接变成成品里的错句。
裁切后每个区域只剩 1 个气泡，模型不需要做版面切分，误差从「句子级」降到「字形级」。

## 五、复跑方法

```powershell
.\.venv\Scripts\python.exe scripts\make_region_sheet.py `
  "<数据根目录>\_300dpi_简\七龍珠 全彩版" "七龍珠 全彩版 第17卷" 0125 0147 `
  --out-dir "$env:TEMP\opencode\bench"

# 把两张 *_sheet.png 分别发给候选模型，要求 {"#k": "文字"} 的 JSON
# 与本文第二节的标准答案逐格比对（编辑距离），记录实质错误与字符准确率
```
