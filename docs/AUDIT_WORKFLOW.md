## 0. 一句话流程

一卷 → 制带编号联系表 → **逐页核对**（图上原字 vs 入库文字，逐格）→ 汇总修正 →
补漏检气泡 → 一次性重排 → 还原非主体页 → 抽验 → 写 PROGRESS 与 pagedreview。

## 1. 为什么必须逐页核对（三类缺陷，只有逐页才能发现）

| 类型 | 例子（18 卷实测） | audit_diff 能看到吗 |
|---|---|---|
| 转录误认/漏字 | 0007#3 漏「可」、0018#6 漏「沉」、0143「嘖」读成「哼」 | 看不到（它比的是同一份旧 OCR） |
| 重复字丢字 | 「呵呵呵」只剩「呵呵」（0140/0154/0216/0228 各一处） | 看不到 |
| **漏检气泡** | 0023「什麼？」、0030「球——！」、0148「交換——！」、0154「那麼，」 | **完全看不到**（区域不在 pages.json 里，成品留着繁体/空白） |

结论：`audit_diff` 只能算「全卷视觉转录」的体检，**不等于交付**。

## 2. 角色分工（谁能定稿）

| 角色 | 做什么 | 不能做什么 |
|---|---|---|
| **deepseek-v4.1-flash**（主跑模型） | 逐页比对，报差异 + 报漏检气泡（带 bbox） | 不能给自己报的差异下结论 |
| **muse-spark-1.3-contributor** | 争议格的第二意见 | 单独跑会漏（实测：判「全对」的区间里藏 4 处漏字），也会误报（多字、呜→鸣） |
| **人/主会话** | 裁决冲突、抽检、确认补框位置 | 不能把两个模型的「同意」当成事实（0023 那条两个模型都错） |

**定稿规则**

1. 主跑模型报的差异 → 直接进 `review.json`（数量少、可信度高）；
2. 同一格被第二个模型否掉、或主跑模型自己前后不一致 → **人看图裁决**；
3. 裁决结果写进 `review.json` 的 `_rejected` 字段（附理由与出处），**以后不许翻案**；
4. 看不清的格写 `?`，留在页面上比猜好。

## 3. 每卷标准动作（A→G）

命令一律 `.\\.venv\\Scripts\\python.exe`，工作目录为仓库根目录。
下文 `<系列>` 例如 `<数据根目录>\\_300dpi_简\\死神 (全74卷)`，
`<卷名>` 例如 `死神 第01卷`，`<NN>` 是卷号两位（trans 目录用）。

### A. 制表（一次性）

```powershell
.\\.venv\\Scripts\\python.exe scripts\\make_region_sheet.py "<系列>" "<卷名>" --all --out-dir "$env:TEMP\\opencode\\sheets<NN>"
```

一张表 = 一页的**所有已检测区域**裁图 + 红色 `#序号`。序号就是 `text.jsonl` 里的下标。

### B. 逐页核对（核心，分 15 页一批）

每批一个子代理，模型 **deepseek-v4.1-flash**，提示词骨架：

```
工作目录 <仓库根目录>。逐页核对 <卷名> <lo>–<hi> 页。
1) 先跑：.\.venv\Scripts\python.exe scripts\dump_final.py "<系列>" "<卷名>" <lo> <hi>
   （每行一页：页码 | 序号:入库文字 | ...）
2) 逐页看：%TEMP%\opencode\sheets<NN>\<页码>_sheet.png
   （红字 #序号 对应文字里的序号；没有该页文件＝无字页，跳过）
3) 逐格比：图上原字 ↔ 入库文字。只报确实不一致的格。
   重点：漏字/多字（长句吞字）、形近字、重复字丢字（呵呵呵→呵呵、啊啊啊→啊啊）。
   额外任务：气泡上有字但成品没抹/没排（仍是繁体或空白）→ 列到 _missing，给 bbox。
4) 不报：风格、标点偏好、繁简、拟声词/美术字、页脚版式字、史考特屏幕数字。
   看不清写 "?"，绝不猜。
只输出 JSON：
{"0012.jpg": {"3": "正确文字"}, "_missing": {"0023.jpg": [{"text": "什么？", "bbox": [895,923,69,157]}]}, "_checked": ["0005","0006","0007"]}
全对输出 {}。`_checked` 必须列出**你实际打开并逐格比过的页**（少列＝这页算没核对）。
末尾写一行 `核对页数：N`（应等于 _checked 的长度）。
```

派发规则：一次最多 4–5 个并发；**滚动派发**——保持 4–5 个在飞，每回来一批立刻补派下一批，
不要等整波收齐（等最慢那批会白白拖 5–10 分钟）。每批必须回 `核对页数`，**没有回执的行当失败重发**。
**断点续跑**：派发前先读 `<卷名>.coverage.json`（若有），已在 `_checked` 里的页跳过不重派；
中断重跑只补缺口不从头来。coverage 在汇总时增量合并，`check_coverage.py` 是唯一验收口。

### C. 汇总 + 覆盖率体检

1. 把每批 JSON 合并进 `<系列>\<卷名>.review.json`（页 → 序号 → 文字），`_missing` 合并进
   `<系列>\<卷名>.extra.json`，`_checked` 合并进 `<系列>\<卷名>.coverage.json`
   （`{"checked": [...], "batches": [{"range": [...], "pages": N}]}`）。
2. **覆盖率必须 100%**：

```powershell
.\\.venv\\Scripts\\python.exe scripts\\check_coverage.py "<系列>" "<卷名>" --sheets "$env:TEMP\\opencode\\sheets<NN>" --skip <非主体页...>
```

打印「覆盖率 100%」才准往下走；有缺口就是有页没真正核对，补派那几页，**不许 `--finish`**。
`--skip` 必须和后面 `restore_pages.py` 用的是同一份非主体页清单，否则会把封面/附录算成缺口。

### D. 补框必须裁图确认（**最容易踩的坑**）

漏检气泡有**两条证据链**（20 卷实测：17 个补框里 15 个来自第 2 条）：

1. 逐页核对时模型报的 `_missing`（联系表只裁已检测区域其实**看不见**漏检气泡，这条只能当线索宁可信其有）；
2. **`detect_extra.py` 全卷重跑 + 与已有框做差集**（这条才是真正管用的找法）：
   `detect_extra.py "<系列>" "<卷名>" <漏检可疑页...> --threshold 0.12` 跑完全卷主体页，
   与 `text.jsonl` 已有框求差，过滤页脚/整格边框后**逐张裁图看**，确认是印刷体对话气泡才进 `extra.json`。
   手写体/彩色美术字/拟声字即使漏了也不补（按 §4 口径保留原图）。

1. `bbox` 用**处理坐标（1020×1600）**，不是成品像素；成品页是 1932×3030（×1.894）。
2. 抠图核对：

```python
SCALE = 1932 / 1020
box = (x*SCALE, y*SCALE, (x+w)*SCALE, (y+h)*SCALE)
```

3. 框错会**抹掉画面上的人物/网点**（18 卷 0154 第一次框落在角色手臂上，重做一次才对）。
4. `detect_extra.py` 的候选框**不可直接用**（它给 0154 的框是空的）。它的价值是提示「这页可能还有气泡」。

### E. 应用修正 + 重排 + 还原

```powershell
# 1) 修正写进 trans 批次与 fix.json（转录目录找不到该页时会只写 fix）
.\\.venv\\Scripts\\python.exe scripts\\apply_review.py "<系列>" "<卷名>" "<系列>\\<卷名>.review.json" --trans-dir "$env:TEMP\\opencode\\trans<NN>"

# 2) 重排（读 fix.json + extra.json；重建整卷 cbz，不是增量）
.\\.venv\\Scripts\\python.exe scripts\\retext_volume.py "<系列>" "<卷名>" "<系列>\\<卷名>.fix.json"

# 3) 还原非主体页（必须在最后）
.\\.venv\\Scripts\\python.exe scripts\\restore_pages.py "<系列>" "<卷名>" <非主体页...>
```

**注意**：`retext_volume.py` 每次重建整卷（18 卷 248 页约 8–10 分钟），没有单页模式。
改一页也要整卷重跑——所以**同一卷的修正要攒齐再跑**。

### F. 抽验（≥3 页，必须真看图）

```powershell
# 从成品 cbz 取页，逐页看图确认：竖排右起、纯黑实心、页脚原样、补框处没抹坏画面
```

### G. 收尾

0. **占位符体检**（必做）：`fix.json` 里出现「？」单独成格 = 占位符被当译文排上去了，
   成品会印出一个问号（19 卷 0100#5、0139#3 实测）。占位符一律写**空串**＝保留原图。
```powershell
.\.venv\Scripts\python.exe -c "import json,pathlib; p=pathlib.Path(r'<系列>\<卷名>.fix.json'); d=json.loads(p.read_text(encoding='utf-8')); print([(k,v) for k,c in d.items() if not k.startswith('_') for v in c.values() if v.strip() in ('?','？')])"
```
1. 更新 `PROGRESS.md` 该卷一行——**必须用脚本，别手改**（两个 worker 并行时手改会互相覆盖）：
```powershell
.\\.venv\\Scripts\\python.exe scripts\\mark_progress.py "<卷名>" "视觉重审：**全卷逐页核对完成**（N 页 M 格修正 + K 处补框）、重排 P 页、还原 Q 页" "P / 总页数"
```
它会加文件锁、只改目标行、原子写。
2. 写 `<卷名>.pagedreview.md`：数字、典型错误类型、`_rejected` 清单、下一轮接续点
3. 磁盘清理（可选）：`sheets<NN>` 每卷约 45 MB，确认本卷收尾后可删；`trans<NN>` 留着便于复现
4. `--finish "<卷名>"` 记日志 + 放卷锁

## 4. 判定口径（改什么 / 不改什么）

**该改**：漏字、多字、形近字（倖/仅、呜/鸣、嘖/啧）、语序错、台湾用语（好康→好处）、重复字丢字、拟声数量错。

**不该改**：
- 风格与标点偏好（省略号点数、逗号位置）
- 繁简差异（目标就是简体，转过去即可）
- 拟声词、手写体、彩色美术字、招式大字 → **保留原图**
- 页脚版式字（`弗力札篇——3★86`）→ 保留原图
- **史考特屏幕上的数字**（90000/110000…）→ 跨语言，保留原图
- 「哦/喔」「那/哪」这类用字习惯 → 不算错

## 5. 非主体页（不参与比对、最后用原图盖回）

封面/书脊、目录、扉页、版权、广告、Q&A 附录、下集预告、封底。
各系列实测位置（新卷先 `dump_final` 看两端的文字再定）：
- 七龍珠：`0001–0004` + 末 4–6 页
- 死神/灌篮/海贼：按卷实测，固定后写进该系列 PROGRESS 备注

## 6. 并发：按卷认领 + GPU 互斥

一卷只许一个执行者，但**允许多个 worker 并行做不同卷**。两个锁：

| 锁 | 位置 | 作用 | 过期 |
|---|---|---|---|
| 卷锁 | `%TEMP%\opencode\locks\<系列>__<卷>.lock` | 认领某卷，别人跳过这卷去拿下一卷 | 60 分钟（`audit_status.py` 的 `VOL_STALE_MIN`） |
| 工人槽 | `%TEMP%\opencode\locks\slot_<worker>.lock` | **一个工人同时只允许一轮在跑**（防止 5 分钟一次的定时器把自己的轮次叠起来） | 60 分钟 |
| 续锁 | `audit_status.py --touch "<卷名>" --worker <A|B>` | **每完成一个阶段（制表/每个核对波次/汇总/重排/还原）跑一次**，卷锁 + 工人槽同时刷新；锁在别人手里会拒绝 | — |
| GPU 锁 | `%TEMP%\opencode\gpu.lock` | 整卷重排（LaMa）独占显卡，避免两个重排撞显存 | 30 分钟 |

**GPU 闸门关闭时的重试分档（2026-11-10 15:27 优化器；2026-11-11 01:27 优化器把临界档的间隔 60s→30s）**：`--gpu-claim` 会先打印空闲显存，按读数分两档，别一律等满 10 分钟——空闲 **≥1200 MB**（离 `GPU_MIN_FREE_MB=2400` 不到一倍）→ 最多 **10 次 × 30s（约 5 分钟）**，这是唯一值得等的情形；空闲 **<1200 MB**（差 2 倍以上，读数不会自己变好）→ **只试 1 次就收手**，放锁去做别的卷。依据一（15:27）：11-10 09:49–15:27 共约 20 次尝试、每次满 10 次全拒，成功率 **0/20**，读数全程 230–625 MB（占卡者 `comicgen-ui.exe` 常驻约 11.6 GB，是用户在正常用，不是空占窗口）。依据二（11-11 01:27，本轮把间隔砍半的证据）：当晚 22:55 起 `comicgen-ui.exe`（PID 25952 那轮）又常驻 10.9 GB，临界档读数 **1500–2100 MB**，五卷（06/08/09/10/11）自述「10 次 / 13 次 / 20 次 GPU 探针」共 **63 次探针、成功率 0/63**，每卷都白等满 10 分钟后 `--release` —— 探测次数保留（10 次，窗口捕捉不变），只把间隔砍半，白等从 10 分钟压到 5 分钟。窗口捕捉没被削弱：`0b` 清扫每次开工各试一次，临界档仍探满 10 次。**绝对不许**为了绕过闸门去结束别人的进程、降 `GPU_MIN_FREE_MB`、或跳过 GPU 锁硬跑重排。

**计时器只决定"要不要去看"，不决定"能不能放"。** 卷锁静默超过 50 分钟先查证持有者是否还活着
（对应卷目录有没有近期产物、`session.list` 里该工人是否 `busy`），确认已死才 `--release`；
只按计时器放锁会让仍在跑长命令（整卷重排/打包常超 50 分钟）的卷被第二个工人重复认领，
代价是整卷返工，远大于多等 10 分钟。脚本侧的 `VOL_STALE_MIN=60` 比这个观察触发线宽，
就是为了让"看"早于"放"。

**锁文件只由脚本产生**：`--claim` / `--touch` / `--gpu-claim` 都用真实系列目录名拼锁名。
手工 `New-Item` 补锁极易拼错（实测 11-07 20:54 有人补了 `七龙珠全彩版__七龙珠全彩版第23卷.lock`，
比真目录 `七龍珠 全彩版` 少一个「龍」→ 这把锁对任何一方的 `claim`/`touch` 都不起作用，等于没锁）。
巡检看到锁名对不上真实系列的，直接删（它不是任何人正在用的卷锁）；要给某卷加保护只能用
`--touch "<卷名>" --worker <X>`。

锁名由 `audit_status.py` 的 `_key()` 生成，**空格和半角括号会被去掉**（`七龍珠 全彩版` + `第27卷`
→ `七龍珠全彩版__七龍珠全彩版第27卷.lock`）。所以锁文件名里没有空格是**正常的、不是拼错**；
判断锁名对不对只看汉字与卷名（龙/龍、第27/第28），别拿空格当依据（11-07 22:05 有轮次误判
「锁名少空格使 claim/touch 失效」，白查一轮）。

```powershell
# 认领（自动跳过别人正在做的卷，按系列优先级取第一个可做的）
.\\.venv\\Scripts\\python.exe scripts\\audit_status.py --claim --worker A
# 没有可认领的卷 → 打印 <<<没有可认领的卷>>>，本轮结束

# 重排前后（拿不到就等，别硬跑）
.\\.venv\\Scripts\\python.exe scripts\\audit_status.py --gpu-claim --worker A
.\\.venv\\Scripts\\python.exe scripts\\audit_status.py --gpu-release

# 收尾（记一条 finish 日志 + 释放卷锁）
.\\.venv\\Scripts\\python.exe scripts\\audit_status.py --finish "<卷名>"
# 中途放弃：释放认领并把接续点写进 PROGRESS
.\\.venv\\Scripts\\python.exe scripts\\audit_status.py --release "<卷名>"
```

中间件目录带卷号：`sheets<NN>` / `trans<NN>`；同卷重做先把旧批次挪进 `trans<NN>_old/`。

## 7. 巡检与跟踪（不要靠猜状态）

```powershell
.\\.venv\\Scripts\\python.exe scripts\\audit_status.py --track     # 剩余卷数 / 队首 / 分钟每卷 / ETA
.\\.venv\\Scripts\\python.exe scripts\\audit_status.py --queue     # 全局下一卷（不认领）
.\\.venv\\Scripts\\python.exe scripts\\audit_status.py             # 某系列逐卷产物时间
.\\.venv\\Scripts\\python.exe scripts\\audit_status.py --all       # 该系列全部卷
```

全部只读（认领/跟踪才写 TEMP 下的锁与日志）。**「该做哪一卷」以 `--queue` / `--claim` 为准，不要自己解析 PROGRESS。**

**`--queue` / `--track` / `--all` 打印的「队首／接下来」不排除已被认领的卷**：脚本只按「未完成」排序，不读锁，
队首很可能正是某个工人在做的卷（11-09 22:27 实测：队首打印「死神 第31卷」，而 31/32/33 三卷同时在飞）。
「下一个可认领」只看 `--claim` 的返回（它跳过热锁）；算「还剩几卷到某个卡点」时按**未登记卷的顺序**推，别把队首当进度指针。

运行日志：`%TEMP%\opencode\audit_runs.jsonl`，每次 claim / finish / release 一行，
`--track` 用它算节奏和 ETA。想加第二个 worker 时，把它的 cron 错开 5 分钟即可。
**`--track` 的「日志累计完成」按 finish 记录数计、不去重**：同一卷重复 finish（失败重跑、复核重排）会让它偏高——11-08 13:27 实测 28 条 finish 只对应 **26 个不同卷**（七龍珠第22卷、死神 第01卷 各两条），ETA 因此偏乐观约 8%。**判节奏/ETA 一律按「不同卷」去重后再算**（与 PROGRESS 已完成数对得上才算准）；这是脚本口径问题（需决策 13），不是工人漏做或重做。

## 8. 停止条件（触发就停手，把状态写进 PROGRESS）

1. 某区间回执 `核对页数` < 应核对页数 → 该批作废重发（不许当成「全对」）
2. 同一卷 `_rejected` 超过 5 条 → 停，等人裁决（说明模型这卷不稳）
3. 补框裁图后位置可疑（压到人物/网点）→ 停，改坐标，别带着错框重排
4. `retext_volume.py` 报错或产物页数 ≠ 原页数 → 停，别覆盖好的 cbz
5. 磁盘剩余 < 5 GB → 停

## 12. 三层结构（谁负责什么、谁能调什么）

| 层 | 谁 | 周期 | 能做什么 | 不能碰 |
|---|---|---|---|---|
| 做卷 | 工人 A / B / C / D（定时任务） | 每 5 分钟（A `*/5`、B `3,8,13,…`、C `1,6,11,…`、D `4,9,14,…`；2026-11-08 06:27 起两人、2026-11-09 18:31 加 C、2026-11-10 19:42 主会话加 D） | 认领一卷按 §3 A→G 做完（claim 代码硬拦一人多卷） | 别人的卷、PROGRESS 手改以外的事 |
| 巡检+有限调整 | 观察员（定时任务） | 每 30 分钟 | 放死锁、刷新跟踪、调数字参数（≤50%，每轮一项） | 流程结构、红线、任务增减、任何卷文件 |
| 优化决策 | 优化器（定时任务） | 每小时 | 上面所有 + 改工人提示词（红线原样保留）+ 工人数量 2↔3 + 文档措辞澄清；每轮最多两项 | §3步骤/§4口径/§8停止条件、删任务、碰卷文件 |
| 最终决策 | 主会话（人喊才来） | 按需 | 改结构、改口径、增减任务、裁决争议 | — |

权力优先级：只有优化器能改工人/观察员的提示词与 cron；观察员只调数字；工人只做卷。
决策日志：任何一层的调整都记 `AUDIT_DECISIONS.md`（时间/改了什么/证据/回退条件），
下一轮验证恶化就回退；连续两轮恶化 → 该层永久停手只报告。

观察员调整权的笼子（见 §12 本节）：
1. 只调数字（锁窗口/重试次数/并发批数），相对基线浮动 ≤50%，每轮最多一项；
2. 必须有本轮巡检证据，必须记进 `AUDIT_DECISIONS.md`（改了什么/为什么/回退条件）；
3. 下一轮验证恶化就回退；连续两轮恶化 → 停手只报告等主会话；
4. 超出权限（改结构、动红线、任务增减）→ 写进跟踪页「需决策」区不硬调。

## 11. 无人值守运行手册（定时任务用）

1. `--claim --worker <A|B>` 认领一卷（自动跳过别人在做的卷）
2. 按 §3 A→G 做完**这一卷**

4. 更新 PROGRESS + pagedreview
5. `--finish "<卷名>"`（记日志 + 放锁）
6. 收尾四行：`Done / Verified / Remaining / Needs`

一轮只做一卷；跑不完就 `--release` 并把「核对到第几页 / 中间件目录」写进 PROGRESS，下一轮接。
多个 worker 并行时，cron 间隔 5 分钟、彼此错开至少 1 分钟（当前 A `*/5`、B `3,8,13,…`、C `1,6,11,…`），靠卷锁分工、GPU 锁排队；**不要两个人做同一卷**。
（2026-11-08 06:27 优化器：心跳从 10 分钟压到 5 分钟。实测每次「finish→下次 claim」的空转中位数 5.2 分钟、最长 10.2 分钟，全在 cron 网格上；空转占单卷墙钟约 5%。间隔 5 分钟时两人的网格必然只差 1–4 分钟，原来的「错开 5 分钟」在 5 分钟间隔下不可能成立，故改为「至少 2 分钟」，仍保证两次心跳不同时触发。）
`--track` 随时看节奏与 ETA（完成记录存在 `%TEMP%\opencode\audit_runs.jsonl`）。

禁止：跳过逐页核对直接改 PROGRESS 说完成；只看 `audit_diff` 就宣称交付；
不裁图就把 `_missing` 的框写进 `extra.json`；两个模型都报却不看图就直接合并。

## 13. 暂停与续跑（停工/复工手册）

### 停工（pause）
1. 在 OpenChamber 定时任务页把 4 个任务逐个**禁用**（不是删除）：工人 A、工人 B、观察员、优化器。在飞的会话不受影响会继续跑完当前卷——**不要杀会话、不要清 TEMP**。
2. 等在飞轮次收尾：`audit_runs.jsonl` 最后一行是 finish+release 配对；`locks/` 目录空；GPU 锁释放；队首卷无人认领。
3. 快照：手动跑一次 `audit_status.py --track --md`（观察员停了就自己跑），记下队首卷与剩余数，写进 CHANGELOG 当期条目。
4. 什么都不删：`%TEMP%\opencode` 下的 trans/review/coverage/extra/sheets/pagedreview、系列目录产物全保留——续跑靠 coverage 断点续跑，删了等于白做。
5. PROGRESS 保持原样（它是状态文件不是开关）。

本次暂停实录（2026-11-08）：死神 15 已 finish、16 在飞（A 重排中）→ 禁用全部 4 任务 → 等 16 收尾 → 全停。队首死神第17卷。

### 复工（resume）
1. 预检 5 项：磁盘剩余 >5 GB；GPU 空；`locks/` 无超期锁（有→按 §6 查证持有者死活后放）；PROGRESS 队首与 `--queue` 输出一致；`--track` 能跑出数字。
2. 启用顺序：观察员 → A → B → 优化器每隔约 1 分钟逐个启用（让观察员先巡检清场）。赶时间可一次全开——claim/slot/GPU 三锁防撞。
3. 首轮验证（15 分钟内必须看到）：新轮认领的**必须是队首卷**；卷锁 + 槽锁建立；子代理派出（`session.list` 有 busy 子会话）。任一缺失 → 查 schedule 状态 + runs 日志 tail。
4. 续跑坑（必读）：
